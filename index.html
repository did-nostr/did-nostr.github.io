did:nostr

A Nostr key is a decentralized identifier.

Draft spec ↗ GitHub ↗ NIP-98 ↗ CID v1.0 ↗

What is did:nostr?

did:nostr is a W3C DID method in which a Nostr public key is the identifier. There is no registry, no ledger, and nothing to mint — the keypair you already use on Nostr resolves directly to a DID document: 

did:nostr:npub-or-32-byte-hex-public-key

Resolving that DID yields a document describing the key (as a Multikey) and, optionally, an alsoKnownAs link to a WebID — bridging a Nostr identity into the wider WebID / Solid / Verifiable-Credentials world without giving up self-custody of the key.

How resolution works

  1. Start with a pubkey. did:nostr:<hex> — the x-only secp256k1 public key.
  2. Fetch the DID document from a resolver: a pod's well-known endpoint (/.well-known/did/nostr/<pubkey>), or a Nostr-aware resolver such as nostr.social / nostr.rocks, or by querying relays for the key's metadata.
  3. Read the verification method. The key appears as a Multikey with a publicKeyMultibase value, referenced from authentication.
  4. Follow alsoKnownAs (if present) to the controller's WebID profile — which declares the same key as a verification method, closing the loop both ways.
  5. Authenticate. The same key signs requests (NIP-98 over HTTP), so resolution and auth share one keypair.

The DID document

What a resolver returns for a did:nostr identifier:

{
  "@context": [
    "https://www.w3.org/ns/cid/v1",
    "https://w3id.org/nostr/context"
  ],
  "id": "did:nostr:<pubkey>",
  "type": "DIDNostr",
  "alsoKnownAs": ["https://alice.example/profile/card#me"],
  "verificationMethod": [{
    "id": "did:nostr:<pubkey>#key1",
    "type": "Multikey",
    "controller": "did:nostr:<pubkey>",
    "publicKeyMultibase": "<f-form multibase of the secp256k1 key>"
  }],
  "authentication": ["did:nostr:<pubkey>#key1"]
}

Multikey and publicKeyMultibase are defined by Controlled Identifiers v1.0; the nostr/context adds the Nostr-specific terms.

Specification & standards

  • nostrcg/did-nostr — the did:nostr method draft, in the Nostr Community Group unofficial draft
  • nostrcg/schema — Nostr web vocabulary / schema (the nostr/context terms) · vocab
  • W3C Controlled Identifiers v1.0 — defines Multikey / publicKeyMultibase

Bridges

  • did:nostr ↔ WebID / Solid — alsoKnownAs links a Nostr key to a Solid identity; the WebID profile declares the same key as a verification method
  • did:nostr ↔ NIP-98 — one keypair resolves and authenticates (nip98.com)

Resolver coming soon

A live resolver — paste an npub or hex pubkey and watch its did:nostr document resolve in the browser — is planned. It will run the full resolution chain (pod well-known endpoints + Nostr relays), not a single host.

Standards

did:nostr builds on W3C DID Core and Controlled Identifiers v1.0. The method draft is developed openly in the Nostr Community Group; this site is an independent hub and does not imply Community-Group consensus.
